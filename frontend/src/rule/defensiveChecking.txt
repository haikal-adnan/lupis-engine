ATURAN PENULISAN KODE (CODE GENERATION GUIDELINES)
1. FOKUS KEPADA FUNGSI UTAMA & EFEKTIVITAS KODE
Tulis kode secara langsung mengeksekusi logika utama (happy path) tanpa boilerplate atau abstraksi berlebihan.

Hindari defensive programming ganda pada data internal/state yang strukturnya sudah terjamin.

2. VALIDASI & PENGECEKAN TEPAT SASARAN
Validasi Input & User State: Tetap lakukan pengecekan pada input pengguna, form, atau edge cases yang mempengaruhi aliran aplikasi (misal: mengembalikan null, pesan error, atau status early return).

Hindari Pengecekan Redundan: Jangan melakukan verifikasi berulang-ulang untuk properti atau variabel yang sudah divalidasi di layer atas/sebelumnya.

Penggunaan Optional Chaining (?.) & Nullish Coalescing (??): Diizinkan untuk akses data opsional atau pembentukan nilai default secara ringkas dan bersih.

3. ASUMSI DATA INTERNAL & STATE
Untuk internal API call, store state, atau objek yang mengikuti kontrak/skema ketat, asumsikan struktur data sesuai spesifikasi tanpa perlu membungkus setiap akses properti dengan pengecekan bertingkat.

4. STRUKTUR DATA BERBASIS SKEMA
Gunakan fungsi skema (contoh: opfsSchema, opfsItemSchema) untuk menginisialisasi dan membentuk struktur data awal.

Hindari sanitasi manual yang berlebihan di luar skema yang telah ditetapkan.

5. PENANGANAN ERROR (ERROR HANDLING)
Tangani error pada batas sistem (system boundary), seperti I/O, network request, atau alur transaksi kritis.

Pada logika internal/bisnis, biarkan error terlempar secara alami jika terjadi kegagalan agar dapat terdeteksi oleh penguji (testing framework) atau logger utama.
